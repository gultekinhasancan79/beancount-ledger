### Additional observations that answer the checklist

| Checklist item | Verdict |
|----------------|----------|
| **(1) Private seed / namespace:index / graph‑digest → public surface** | Leaked via **prompt month** (1) and **world.id** (2). Both are public and derived from the private seed. |
| **(2) Non‑determinism** | No use of `hash()`, `datetime.now()`, locale‑dependent sorting, or unordered dict iteration that influences output. All random draws are from deterministic `random.Random` sub‑streams. Minor nit (7, 9) noted. |
| **(3) Adding a new purpose** | Safe – sub‑streams are independent. Adding a new purpose *does not* reshuffle existing draws. **Adding a new content entry** (new stem, suffix, etc.) *does* change draws that depend on that pool, so a `GENERATOR_VERSION` bump is required whenever any of the content pools (`C.STEMS`, `C.COMPANY_STEMS`, `C.BANK_STEMS`, suffix dicts, etc.) are modified. |
| **(4) Train / eval disjoint & brute‑force** | Disjoint by construction (`private_seed` hashes the namespace string). However, the **public prompt month** reduces the seed space dramatically; an attacker who knows the namespace can enumerate plausible indices (e.g. 0‑10 000) and filter by month, then verify the public task id. This makes brute‑forcing the seed *feasible* for low‑index worlds. |
| **(5) Derived answer vs fact** | The **bank opening balance** (lines 718‑719) is a computed figure, not a fact drawn from a sub‑stream, violating the “author facts only” guarantee. All other amounts, dates, parties, etc., are drawn from sub‑streams, so they are fine. |

### Recommended fixes

1. **Remove month from the prompt** or make the month a separate public field that is also hashed into the task‑id (so the public id binds the month).  
2. **Do not embed private‑seed‑derived data in `world.id`** – replace it with a deterministic opaque identifier (e.g. hash of the whole world after generation).  
3. **Draw the bank opening balance from its own sub‑stream** (e.g. `_rng(seed, "bank_opening").randint(...)`) instead of computing it from flows.  
4. **Document and enforce** that any change to content pools (`C.STEMS`, suffixes, `C.FAMILIES`, etc.) requires a bump of `GENERATOR_VERSION`.  
5. **Consider adding the prompt to the public‑task‑id hash** if the prompt must stay as is, to keep the id a true provenance hash.  
6. **Add a sanity check** that `minted.world.id` does not contain any substring that can be traced back to the private seed (similar to `leaks_provenance`).  

These concrete issues demonstrate that the current implementation does **not** fully satisfy the deterministic‑reward, non‑interference guarantees claimed in the module docstrings.
